# Knowledge-Base Structure

*Elevate Accounting. Where the onboarding standard lives, so it stops being scattered across systems and heads.*

One of the discovery findings was that templates and process knowledge are scattered across systems, so people reinvent them. This is the fix: a single, well-organised home for the onboarding standard, in SharePoint (which Elevate already uses), structured so anyone can find the current version of anything in seconds and nobody works from an old copy.

## Principles

- **One home, one current version.** Everything onboarding lives in one SharePoint area. No parallel copies in personal drives. If it is not here, it is not the standard.
- **Owned, dated, versioned.** Every item has a named owner and a last-reviewed date, so staff can trust it is current.
- **Structured to the journey.** The folders follow the onboarding journey and the service lines, so the structure itself teaches the process.
- **Editable by design.** Templates, prompts and checklists are editable (the brief requires this) and stored where the owner can update them.

## Folder structure (SharePoint)

```
Client Onboarding/
├─ 00_Start_here/
│    ├─ The common journey (one page)          [owner: Practice Manager]
│    ├─ Ways of working (the assistant + tracker in brief)
│    └─ Who owns what (roles)
├─ 01_The_standard/
│    ├─ Common journey and service-line variants
│    ├─ Document-request matrix and completeness rules
│    └─ Standard onboarding checklist (with variants)
├─ 02_The_assistant/
│    ├─ Prompt library (welcome, document request, reminders, briefing, handover)
│    ├─ Claude Project setup guide
│    └─ Email library (the firm's warm standard messages)
├─ 03_The_tracker/
│    ├─ How to use the tracker
│    └─ Dashboard specification
├─ 04_Service_lines/
│    ├─ Business advisory (variant notes, examples)
│    ├─ Tax compliance (variant notes, examples)
│    └─ Bookkeeping (variant notes, examples)
├─ 05_Staff_guidance/
│    ├─ SOP: run an onboarding with the assistant
│    ├─ SOP: manage the tracker and stalls
│    └─ Training pack
└─ 06_Improvement/
     ├─ Suggestions and issues log
     └─ Change history (what changed, when, why)
```

## What lives where, and who owns it

| Area | Contains | Owner |
|---|---|---|
| 00 Start here | The one-page orientation for any staff member or new starter | Practice Manager |
| 01 The standard | The journey, matrix, completeness rules, checklist, the source of truth | Practice Manager |
| 02 The assistant | Prompts, Claude Project guide, email library | Practice Manager |
| 03 The tracker | How-to and the dashboard spec | Practice Manager |
| 04 Service lines | Per-line variant detail and de-identified examples | Service-line partners |
| 05 Staff guidance | SOPs and the training pack | Practice Manager |
| 06 Improvement | The suggestions log and change history | Practice Manager |

## Keeping it alive

- **Quarterly review.** The Practice Manager confirms each item's last-reviewed date, and updates anything a service line has changed.
- **One change log.** Every change to the standard is noted in 06, so staff can see what changed and when, and trust that 01 is always current.
- **Feedback loop.** Staff drop suggestions and snags into the log in 06; the good ones become improvements to the matrix, prompts or checklist. The standard gets better because the people using it feed it, not because someone rewrites it once a year.

The result: the onboarding knowledge that used to live in inboxes and individual habits now lives in one place, current, owned, and easy to find, which is what makes the standard hold rather than drift back to "everyone does it their own way."
