# The Common Onboarding Journey, with Service-Line Variants

*Elevate Accounting. One journey for the whole firm, with the differences made explicit instead of left to memory.*

The point of this document is to end the "every accountant does it differently" problem. There is now **one journey**. Business advisory, tax compliance and bookkeeping are not three separate processes; they are the same journey with a small, named set of differences. Anyone at Elevate can follow it, and a client gets the same quality whoever picks them up.

## The common journey (all service lines)

Seven steps, each with an owner and a clear "done" test.

```
  1. ENGAGE        Client agrees to proceed
        |          Owner: partner/accountant · Done: engagement recorded in Xero PM + HubSpot
        v
  2. WELCOME       Personal welcome + what happens next
        |          Owner: client owner · Done: welcome sent (assistant drafts, owner sends)
        v
  3. SCOPE         Confirm service line + any specifics
        |          Owner: client owner · Done: service line + variant set; exceptions flagged
        v
  4. REQUEST       Send the right document request (from the matrix)
        |          Owner: client owner · Done: request sent; items tracked as outstanding
        v
  5. COLLECT       Documents arrive; reminders as needed
        |          Owner: client owner + assistant reminders · Done: completeness rule met (see doc 04)
        v
  6. SET UP        Client set up in systems; engagement letter signed
        |          Owner: accountant · Done: Xero/FYI set up; Adobe Sign complete
        v
  7. FIRST MEETING Ready, informed first advisory meeting + warm handover
                   Owner: accountant · Done: briefing pack ready; client handed to ongoing team
```

Every onboarding runs these seven steps in this order. What changes between service lines is only what is inside steps 3, 4 and 5, and that is written down below, not left to the individual.

## The service-line variants

Only the differences are listed. Everything not listed follows the common journey exactly.

### Business advisory (the most involved)

- **Scope specifics:** entity structure, advisory goals, current accounting software, other advisers (planner, lawyer, banker).
- **Documents:** the full set (see matrix), including prior financials, structure diagram, and management accounts if available.
- **Extra step:** a short pre-meeting goals note, so the first advisory meeting starts on strategy, not setup.
- **Exception path:** complex structures (trusts, multiple entities) trigger a partner review before the first meeting.

### Tax compliance (the highest volume)

- **Scope specifics:** entity type, financial year, lodgement history, ATO agent linking.
- **Documents:** identity and TFN/ABN details, prior-year returns, and the compliance document set (see matrix).
- **Exception path:** overdue prior-year lodgements route to a partner to agree an approach before onboarding continues.

### Bookkeeping (the fastest)

- **Scope specifics:** software in use, bank feeds, transaction volume, reporting cadence.
- **Documents:** bank and software access confirmations, chart-of-accounts preferences, the bookkeeping document set (see matrix).
- **Exception path:** a messy or migrating file triggers a scoping call before a start date is committed.

## Exception paths (all service lines)

Exceptions are named so they are handled consistently, not improvised:

- **Identity check cannot be completed** (AML/KYC): onboarding pauses at step 5; the firm's existing identity-verification control runs; the assistant never makes or advises on the determination.
- **Client goes quiet:** the tracker flags a stall after the reminder cadence is exhausted (see doc 04); the owner makes a personal call, not another automated email.
- **Scope is unclear or changes:** return to step 3; re-confirm the service line and variant before requesting documents, so the client is never asked for the wrong things.
- **Complexity beyond the standard:** route to a partner (as per each service line's exception) before proceeding.

## Roles across the journey (who owns what)

| Role | Owns |
|---|---|
| Client owner (accountant or partner) | The relationship and every client message; steps 2-5 |
| Accountant | Setup and the first meeting; steps 6-7 |
| Partner | Exceptions, complex structures, and sign-off on the common process |
| Practice Manager (process owner) | The journey itself, the tracker, and keeping the standard current |
| Client Onboarding Assistant | Drafting and organising only; never an owner, never a decision |

## Why one journey, with variants written down, is the whole fix

The firm's problem was never that the service lines are different; of course they are. The problem was that the differences lived in people's heads, so the *common* parts got reinvented too. Writing the journey once, and naming exactly what changes per service line and what to do in each exception, means a client gets the same warm, organised experience whoever they land with, and a new staff member can run a good onboarding on day one. The assistant and the tracker in the rest of this repository simply make this journey easy to follow and easy to see.
